# Task 1: Stakeholder Analysis Matrix

The table below synthesizes the findings across all principal actors within the Omnichannel Order Fulfilment Platform, detailing their operational responsibilities, primary concerns, architectural needs, and assigned prioritization.

| Stakeholder Role | Primary Responsibilities | Core Pain Points & Risks | Architectural & Design Response | System Priority |
| :--- | :--- | :--- | :--- | :--- |
| **Customer** | - Browse catalogue<br>- Add to cart & checkout<br>- Track delivery status<br>- Initiate return requests | - Overselling / cart drops<br>- Duplicate billing on retry<br>- Unclear order progress<br>- Privacy breaches | - Server-side tax & price calculation<br>- Atomic stock reservation (15-min lease)<br>- Deduplicated payment callbacks<br>- Customer-scoped order queries | **High (Must)** |
| **Warehouse Picker** | - Inspect assigned pick lists<br>- Physically retrieve items<br>- Confirm pick and pack<br>- Hand off to couriers | - Picking cancelled/expired orders<br>- Inventory inaccuracies<br>- Ambiguous item bin locations | - Strict lifecycle guard (`PAID` -> `PACKED` -> `DISPATCHED`)<br>- Pickers see only paid orders assigned to their warehouse<br>- Explicit pick confirmation required before dispatch | **High (Must)** |
| **Support Agent** | - Look up customer orders<br>- Investigate delivery status<br>- Initiate return requests on customer behalf | - Lack of tracking visibility<br>- Exposing sensitive payment data to staff<br>- Impersonation attacks | - Masked data projection (name/partial phone/order status)<br>- Exclusion of PAN/CVV from database & API<br>- Permission to request return, but zero refund approval privileges | **Medium (Should)** |
| **Finance Reviewer** | - Review high-value refunds<br>- Verify financial reconciliations<br>- Audit payment callback events | - Unaudited money outflows<br>- Gateway retry double-debits<br>- Lack of separation of duties | - Dual-control refund workflow (`REQUESTED` -> `APPROVED` -> `EXECUTED`)<br>- Server-enforced refund threshold (\$50.00)<br>- Idempotent refund execution with retry retention | **Critical (Must)** |
| **Store Manager** | - Oversee store fulfilment<br>- Monitor inventory depletion<br>- Analyze regional sales & returns | - Analytical queries slowing checkout transactions<br>- Data discrepancies across regions | - Decoupled reporting view / materialized summary tables<br>- Regional breakdown metrics with periodic background refresh | **Medium (Should)** |
| **Administrator** | - Manage users & role assignments<br>- Configure regional policies (tax, shipping, refund)<br>- Audit compliance logs | - Privilege escalation via client-side tampering<br>- Untracked policy modifications | - Server-side RBAC validation on every request<br>- Append-only immutable audit trail with actor, timestamp & versioning<br>- Versioned regional policy records | **High (Must)** |
| **Payment Gateway (External)** | - Authorize transactions<br>- Transmit signed webhook callbacks | - Network timeouts<br>- At-least-once delivery duplicates | - HMAC-SHA256 signature verification<br>- Unique constraint on `(gateway_id, event_id)`<br>- Outbox pattern for downstream actions | **Critical (Must)** |
| **Courier API (External)** | - Ingest shipment requests<br>- Provide parcel tracking updates | - Upstream API outages<br>- Socket disconnects during booking | - Asynchronous Transactional Outbox worker<br>- Correlation key reconciliation before retry<br>- Retry with exponential backoff | **High (Must)** |
| **Warehouse Scanner (Edge)** | - Scan barcodes at receiving & packing bins<br>- Buffer events during WiFi loss | - Intermittent warehouse dead zones<br>- Batch replays causing double stock increments | - Edge-node event buffering with UUIDs<br>- Server-side batch deduplication by `(node_id, event_id)`<br>- Stale observation timestamp evaluation | **High (Must)** |
