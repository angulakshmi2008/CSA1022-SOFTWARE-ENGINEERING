# Task 2: Non-Functional Requirements Specification

The system specifies 8 testable Non-Functional Requirements (NFR01 through NFR08). All vague performance or reliability goals have been replaced with precise operating conditions, quantitative metrics, and observable verification criteria.

| ID | Quality Attribute | Precise Requirement & Target Metric | Operating Condition | Observable Acceptance Evidence |
| :--- | :--- | :--- | :--- | :--- |
| **NFR01** | Performance & Latency | The checkout endpoint (`POST /api/orders`) shall achieve a 95th percentile (p95) response time under **800 ms** and a median (p50) under **250 ms**, excluding external third-party network latency. | Sustained steady-state load of 50 concurrent synthetic customer sessions over a 10-minute measurement window on the reference host. | Performance benchmark report recording p50, p95, p99 latencies, CPU utilization, database query durations, and error rates (< 0.1%). |
| **NFR02** | Transactional Consistency | Under peak concurrency, the platform shall enforce strict serializability for inventory and payment deduplication. Available stock (`on_hand - reserved`) shall **never become negative**, and a single gateway event shall result in at most one payment record. | Concurrent execution of 20 threads submitting competing orders for the final 5 units of stock; simultaneous delivery of 10 identical webhook callbacks. | Automated concurrent pytest assertions verifying zero negative stock records and a database unique constraint violation log with zero duplicate payment rows. |
| **NFR03** | System Recoverability (RTO & RPO) | Following an ungraceful shutdown or crash of the integration worker container, all uncompleted outbox tasks shall resume processing within **15 minutes** (Recovery Time Objective <= 15 min), with **zero data loss** of committed business transactions (Recovery Point Objective = 0). | Deliberate termination (`SIGKILL`) of worker process while 25 courier intents remain pending in `outbox_intents`. | Post-restart audit logs demonstrating that all 25 intents were claimed, retried, and completed without manual operator intervention. |
| **NFR04** | Security & Least Privilege | The platform shall enforce server-side Role-Based Access Control (RBAC) across all six user roles (Customer, Picker, Support, Finance, Manager, Administrator). Under no circumstances shall raw Primary Account Numbers (PAN), CVVs, or card magnetic data be stored in plaintext or database columns. | Role-matrix penetration test executing 50 unauthorized API invocations across all protected endpoints. | Automated security test asserting HTTP 403 Forbidden on all privilege-escalation vectors; database schema inspection verifying total absence of PAN/CVV columns. |
| **NFR05** | Usability & Accessibility | All primary customer checkout flows and staff dashboard workflows shall be 100% operable via keyboard-only navigation (Tab, Enter, Space, Arrow keys). Critical state statuses (`PLACED`, `PAID`, `DISPATCHED`, `REFUNDED`) shall be conveyed through explicit text labels and ARIA descriptors, not color alone. | Standard browser DOM audit using keyboard tab traversal and high-contrast color blindness emulation. | Documented keyboard navigation walkthrough; automated HTML audit verifying that order statuses render with explicit textual badges and accessibility attributes. |
| **NFR06** | Portability & Reproducibility | The complete platform (frontend, backend, database, mock services, test runner) shall be fully reproducible on any clean host operating Docker and Docker Compose with a single command (`docker compose up --build`). | Clean Ubuntu 22.04 LTS or Windows 11 host with Docker Engine 24.0+ and 8 GB RAM. | Verifiable container initialization log demonstrating health-check success across `postgres`, `fastapi-backend`, `outbox-worker`, and `react-frontend`. |
| **NFR07** | Scalability & Regional Expansion | The redesigned architecture shall support planning workloads of **500 simultaneous users** and **1,000 operational events per minute** (~16.7 events/sec average, ~83.3 events/sec peak) across **12 geographic regions** without deadlocking or memory exhaustion. | Simulated multi-region event burst with synthetic traffic generator simulating concurrent checkout, payment callbacks, and scanner syncs. | Measured throughput logs demonstrating sustained processing without unhandled HTTP 500 errors or queue memory leaks. |
| **NFR08** | Maintainability & Audit Traceability | Every domain command affecting financial state, inventory counts, or order lifecycle shall generate a structured audit entry linked to the triggering user ID, timestamp, entity version, and request correlation ID. | 100% of mutating API operations executed across test suite. | SQL verification asserting `COUNT(orders) == COUNT(audit_events WHERE action = 'ORDER_CREATED')` and 100% linkage between refund executions and approval records. |
